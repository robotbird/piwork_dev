# 应用文案国际化

本轮范围是应用代码中的展示文案、提示、接口错误和聊天工具进度。Skill 目录、SKILL.md、技能脚本与资源、内置 Skill 内容不修改；用户输入的名称和内容不翻译。中文匹配规则、历史截断标记、模型系统提示和运行诊断属于行为/协议内容，不依据浏览器语言替换。

## 当前实现

- `i18n/request.ts` 继续按 NEXT_LOCALE cookie、Accept-Language 和默认中文选择语言；中英文资源位于 `i18n/messages/zh.json`、`en.json`。
- 页面/接口使用 next-intl `getTranslations`；客户端使用 `useTranslations` 或既有 `usePreferences().t`。日期使用当前 locale；数量、包含名称的消息和计划描述使用完整 ICU 消息，避免拼接中文后缀。
- 文档分类使用 all/folders/documents/images/spreadsheets/presentations/aiGenerated 标识，显示时才翻译；切换语言保留筛选状态。
- 模型插件已提供双语字段时按当前语言选取原生 label/help/placeholder，不修改插件定义、凭据或模型标识。
- 对话分支标题和 Token 统计中的缺失值按请求语言生成，原对话标题、部门/角色名称和模型身份保持原文。
- 系统角色按 type + code 显示资源中的名称/说明；自定义角色保持用户原文。系统角色播种继续使用原默认中文值，不迁移已有名称。
- `lib/i18n/messages.ts` 使用官方 `use-intl/core` 的 createTranslator，不依赖 React hooks/Next 请求上下文；后台错误维持原默认文本，LocalizedError 额外持有 messageKey/params。DocumentInputError 在 HTTP 边界按当前请求翻译。后台任务已保存的固定提示通过兼容映射展示；不可识别的外部错误保留原文。
- `i18n/legacy-keys.json` 承接旧中文标签与固定错误文本的兼容映射；新代码直接使用翻译键。兼容映射不是新文案的存放位置。
- `lib/chat/tool-status.ts` 只处理平台展示，接收注入的翻译函数。RuntimeEvent → stream-mapping 继续投影 transient data-tool-status，新增可选 detail（与既有 message 中相同的命令/路径摘要），前端按当前语言重新格式化。toolName、事件语义、Pi session/agent loop、后端选择和授权不改变；旧消费者仍可读 message。旧进度无 detail 时可显示本地化工具名称，瞬时进度不做历史迁移。
- ChatbotError 错误码不变，消息移入双语资源；构造器保持原默认英文语义，toResponse 可传 locale（缺省项目默认中文），客户端按错误码与当前语言显示。常规接口的新文案按 getTranslations 的请求语言响应。

## 验证

`pnpm test:i18n` 校验中英文键全集、ICU 参数与格式、数量复数、计划/工具进度/错误、系统与自定义角色边界，并用 TypeScript AST 扫描 app/components/hooks/artifacts 的中文字符串/模板和英文 JSX 文本（注释不参与；品牌与版本前缀明确保留）。这组测试随 test:runtime 收集。

`pnpm test:i18n:ui` 使用隔离 esbuild/Chromium 和模拟 API 验证文档库语言切换后筛选保留、任务周期/状态/编辑器翻译及用户标题保持原文。Next navigation/image/link 的测试替身只在 tests/support/i18n；不访问正式身份、数据库、模型、沙箱或 Skill 目录。

参考 [next-intl 翻译与 ICU](https://next-intl.dev/docs/usage/translations)、[独立核心库](https://next-intl.dev/docs/environments/core-library) 与 [Pi 官方 SDK](https://pi.dev/docs/latest/sdk)。Pi 仍为仓库锁定的 1.1.0；未引入新 Pi API，只在既有平台投影层增加展示字段。
