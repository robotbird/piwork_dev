# OpenAI Unified Interface Design System

**版本**：1.5  
**日期**：2026-09-19  
**适用范围**：AI 对话、Agent/Codex 任务工作台、桌面端设置、审批与危险操作  
**证据来源**：用户提供的 5 张 ChatGPT / Codex 桌面端截图。截图中的对话内容仅作为版式样本，不作为需求或指令。

---

## 1. 设计结论

这套界面的核心不是“极简”，而是**低噪声的高密度工作界面**：让内容与当前任务始终成为视觉主角，用很少的颜色、轻边框和局部浮层建立层级。

新的统一规范采用五条原则：

1. **内容先行**：长文本、代码、文件变更和设置说明拥有最高阅读优先级。
2. **结构安静**：大面积中性色承载结构，避免用色块切割页面。
3. **状态集中**：蓝色只表达可交互、已选择或进行中；红色只表达破坏性动作。
4. **邻近即关联**：操作紧贴其对象，元信息退居次级，不让用户在屏幕两端来回寻找。
5. **渐进揭示**：默认只展示完成当前任务所需的信息，高级能力放进菜单、展开区或二级页面。

### 2.1 共同语言

- 以白色画布和浅灰结构面构成主体，尽量不出现大面积品牌色。
- 侧栏宽而稳定，主内容拥有明确的最大宽度，超宽屏不无限拉长文本。
- 选中态主要依赖浅灰底；蓝色更偏向执行、开关、链接、语音等动态动作。
- 表面之间优先使用 `1px` 轻边框；阴影只服务于悬浮输入器、弹窗、菜单。
- 控件普遍采用胶囊或中等圆角，容器圆角大于内部按钮圆角。
- 主文案黑度高，说明文案降低一到两个层级，但不使用过浅灰。

## 3. 信息架构与布局

### 3.1 应用骨架

```text
┌──────────────┬────────────────────────────────────────────┐
│ Sidebar      │ Top bar / title / global actions           │
│ 240–260 px   ├────────────────────────────────────────────┤
│              │                                            │
│ navigation   │ Centered content column                    │
│ recents      │ chat: 720–800 px / settings: 920–1040 px   │
│ account      │                                            │
│              │              floating composer             │
└──────────────┴────────────────────────────────────────────┘
```

- 桌面端侧栏：`240px`（Codex）或 `260px`（ChatGPT），产品内必须固定一种宽度。
- 顶栏高度：`52–56px`；侧栏项目行高：`36–40px`。
- 对话正文最大宽度：`760px`，推荐行长 `45–75` 个中文字符。
- 工作起始页输入器最大宽度：`920px`；对话页输入器最大宽度与正文保持一致。
- 设置内容最大宽度：`960px`；页面顶部留白 `64–80px`。
- 主内容左右安全边距：桌面 `32px`，平板 `24px`，手机 `16px`。

### 3.2 响应式规则

| 断点 | 导航 | 主内容 | 输入器 |
|---|---|---|---|
| `≥1280px` | 常驻侧栏 | 居中最大宽度 | 底部悬浮或空白态居中 |
| `768–1279px` | 可折叠侧栏 | 自适应，最大宽度不变 | 固定于内容列底部 |
| `<768px` | 抽屉式导航 | 单列，16px 边距 | 贴底，避让安全区与键盘 |

窄屏时禁止简单缩放桌面界面：设置行需要从“左右分栏”转为“上文案、下控件”，弹窗宽度为 `calc(100vw - 32px)`。

## 4. Foundations

### 4.1 颜色

#### 中性色

| Token | 色值 | 用途 |
|---|---:|---|
| `canvas` | `#FFFFFF` | 主画布、卡片、输入区 |
| `surface-subtle` | `#F7F7F8` | 次级背景、工具条 |
| `surface-muted` | `#EFEFF0` | 选中行、悬停态、弱按钮 |
| `surface-strong` | `#E3E3E5` | 按下态、禁用轨道 |
| `border-subtle` | `#ECECEE` | 分隔线 |
| `border-default` | `#DEDFE2` | 卡片、输入器、弹窗边框 |
| `text-primary` | `#171719` | 标题与正文 |
| `text-secondary` | `#67676C` | 说明与元信息 |
| `text-tertiary` | `#929298` | 占位符、低优先级信息 |

#### 语义色

| Token | 色值 | 用途 |
|---|---:|---|
| `accent` | `#3B82F6` | 主操作、链接、开启状态 |
| `accent-hover` | `#2563EB` | 强调控件悬停 |
| `accent-soft` | `#EAF3FF` | 用户气泡、浅选中态 |
| `success` | `#18A957` | 成功、增加、已完成 |
| `danger` | `#E5484D` | 删除、放弃、失败 |
| `danger-soft` | `#FFECEE` | 危险按钮浅底 |
| `warning` | `#B7791F` | 配额、需要注意但非失败 |

**用色纪律**：单屏强调色覆盖面积建议不超过 `8%`。中性选中态优先于蓝色选中态；同一控件不能仅靠颜色表达状态。

### 4.2 字体

首选字体栈：

```css
font-family: ui-sans-serif, -apple-system, BlinkMacSystemFont,
  "SF Pro Text", "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
```

| 样式 | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| Display | `28 / 36` | 600 | 极少量欢迎标题 |
| Page title | `24 / 32` | 600 | 设置页、独立页面标题 |
| Section title | `16 / 24` | 600 | 卡片组、区域标题 |
| Body | `15 / 24` | 400 | 对话正文、说明 |
| Body strong | `15 / 24` | 600 | 关键结论、行标题 |
| UI | `14 / 20` | 450–500 | 导航、按钮、控件 |
| Meta | `12 / 18` | 400–500 | 时间、标签、辅助状态 |

- 中文长文默认 `15–16px`，行高不低于 `1.55`。
- 标题仅采用字重和间距建立层级，不使用全大写或高饱和颜色。
- 代码、路径、模型名使用等宽字体，但字号不得低于 `12px`。

### 4.3 间距、圆角与边框

- 基础单位：`4px`。
- 常用间距：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64`。
- 组件内边距：小控件 `6×10px`，标准按钮 `8×14px`，卡片 `16–20px`，弹窗 `24px`。
- 圆角：`6px`（小控件）、`10px`（按钮/行）、`14px`（卡片）、`22px`（输入器/弹窗）、`999px`（胶囊/开关）。
- 边框：默认 `1px solid border-default`；分组内部使用 `border-subtle`。

### 4.4 阴影与层级

```css
--shadow-float: 0 1px 2px rgb(0 0 0 / .05), 0 8px 24px rgb(0 0 0 / .07);
--shadow-modal: 0 18px 55px rgb(0 0 0 / .16), 0 2px 8px rgb(0 0 0 / .08);
```

| 层级 | z-index | 对象 |
|---|---:|---|
| Base | `0` | 画布、正文 |
| Sticky | `10` | 顶栏、贴底输入器 |
| Popover | `30` | 菜单、选择器、提示 |
| Scrim | `40` | 遮罩 |
| Modal | `50` | 确认弹窗 |
| Toast | `60` | 全局反馈 |

## 5. 核心组件规范

### 5.1 侧栏 Sidebar

**结构**：品牌/产品切换 → 搜索与新建 → 分组导航 → 最近项目/会话 → 配额/账户。  
**尺寸**：宽 `240–260px`；左右内边距 `8–12px`；行高 `36–40px`。  
**状态**：默认透明；Hover 使用 `surface-subtle`；Selected 使用 `surface-muted`；按下使用 `surface-strong`。  
**规则**：长名称单行截断，悬停显示完整标题；图标固定 `18–20px`；项目名称与图标间距 `10–12px`。

### 5.2 复合输入器 Composer

**用途**：统一文本输入、附件、上下文、模型、语音与发送。  
**结构**：状态/配额提示（可选）→ 多行输入区 → 左侧工具 → 右侧模型/语音/发送。  
**尺寸**：最小高度 `64px`，多行态 `112–168px`；圆角 `22px`；边框 `1px`；底部工具行高 `44px`。  
**行为**：

- 输入为空时，发送按钮禁用且降低对比；有内容时转为强调色。
- `Enter` 发送、`Shift+Enter` 换行；必须允许用户改变快捷方式。
- 工具选中后显示可移除的上下文标签，不只改变图标颜色。
- 输入器固定时应为最后一条消息预留等高底部空间，避免遮挡。
- 配额或错误属于输入上下文时置于输入器上方；全局故障使用 Toast/Banner。

### 5.3 消息与任务记录

- Assistant 内容默认不使用大气泡，保持文档式阅读。
- User 消息使用 `accent-soft`，圆角 `18–22px`，最大宽度 `70%`；短消息可自然收缩。
- 消息间距 `28–40px`；段落间距 `12–16px`。
- 消息操作栏包含复制、反馈、分享/重试和更多；默认弱化，Hover 或聚焦时提升对比。
- Codex 任务输出允许使用文件卡、Diff 摘要、审批卡与运行状态；每种产物都要显示对象、状态和下一步。

### 5.4 设置分组与设置行

设置卡采用“标签与说明在左、控件在右”的稳定网格。

| 属性 | 规范 |
|---|---|
| 卡片 | 白底、1px 边框、14px 圆角 |
| 行高 | 最小 `68px`，内容多时自增长 |
| 行内边距 | `14–16px 18–20px` |
| 标题 | `14px / 20px / 600` |
| 说明 | `12–13px / 18px`，最大宽度 `620px` |
| 分隔线 | 从内容起点延伸，避免穿过圆角 |
| 右侧控件 | 固定对齐，控件区宽 `160–220px` |

相关设置必须形成有标题的组；破坏性操作与常规设置分开，放在组底部或独立 Danger Zone。

### 5.5 按钮

| 类型 | 视觉 | 使用场景 |
|---|---|---|
| Primary | 深色或强调色实底、白字 | 单一主动作：保存、运行、确认 |
| Secondary | 浅灰底、深色字 | 继续编辑、取消、辅助动作 |
| Outline | 白底轻边框 | 添加额度、切换模式 |
| Ghost | 透明底 | 工具栏、对象级动作 |
| Danger | `danger-soft` + `danger` 文字 | 删除、放弃更改 |
| Icon | `32–36px` 正方形/圆形 | 搜索、分享、更多 |

标准按钮高度 `36px`，紧凑按钮 `32px`；可触区域最小 `36×36px`，触屏最小 `44×44px`。一组按钮最多一个 Primary 或 Danger。

### 5.6 开关、选择器与分段控制

- Switch：`36×20px`，圆形滑块 `16px`；开启使用 `accent`，关闭使用 `surface-strong`。
- Select：高度 `34–36px`，白底轻边框，右侧箭头；文本与图标保持 `8px` 间距。
- Segmented control：容器 `surface-subtle`，激活项白底、轻阴影；用于 2–4 个互斥模式，不替代页面导航。
- 所有控件必须有可读标签；说明文字不作为唯一标签。

### 5.7 通知与配额状态

- **Inline notice**：与当前输入或任务直接相关，置于对象内部或上方。
- **Banner**：横跨内容列，适合配额耗尽、连接中断、需要授权。
- **Toast**：短时成功反馈，不承载必须决策的信息。
- 文案顺序：发生了什么 → 对用户的影响 → 何时恢复/如何处理 → 主要动作。
- 警告不默认使用红色；红色只用于失败或不可逆风险。

### 5.8 模态框与危险操作

**尺寸**：桌面宽 `440–520px`，圆角 `20–22px`，内边距 `24px`。  
**遮罩**：`rgb(17 17 19 / 18–24%)`，不可通过降低弹窗本身对比来制造层级。  
**结构**：明确标题 → 后果说明 → 可选对象信息 → 右对齐操作。  
**按钮顺序**：安全出口在左，危险动作在右。危险按钮使用浅红底，除非是极高风险最终确认。  
**文案**：用具体结果代替抽象确认，例如“放弃未保存的更改”，避免“确定吗”。

## 6. 交互状态

每个交互组件必须定义：

| 状态 | 视觉要求 |
|---|---|
| Default | 保持低噪声但边界可辨 |
| Hover | 背景或边框提升一级，不改变布局 |
| Pressed | 颜色加深并允许 `scale(.98)`，时长 `80ms` |
| Focus-visible | `2px accent` 外环 + `2px` 偏移 |
| Selected | 背景与文字双重变化；必要时显示勾选/标签 |
| Loading | 保留原尺寸，文案可变但不引起跳动 |
| Disabled | 降低对比并阻止交互，仍保持文字可读 |
| Error | 红色边框 + 错误文字 + 可恢复动作 |

动效时长：微交互 `120–160ms`，面板 `180–240ms`，模态框 `160–200ms`。使用标准 ease-out；支持 `prefers-reduced-motion`。

## 7. 内容与文案

- 按钮使用动词：“保存”“继续编辑”“添加额度”；避免“好的”“确定”。
- 状态文案说明影响：“额度已用完，12:05 重置”，而不是只写“受限”。
- 设置标题是名词或状态，说明文字解释后果，不重复标题。
- 模型名、路径、快捷键、额度等机器信息使用一致格式。
- 截断只用于导航和列表；正文、错误和确认后果不能截断。

## 8. 无障碍与质量门槛

- 正文对比度至少 `4.5:1`；大文字和非文本控件至少 `3:1`。
- 全部功能支持键盘；模态框打开后锁定焦点，`Esc` 关闭非强制弹窗，关闭后焦点回到触发器。
- 图标按钮必须有可访问名称和 Tooltip；Tooltip 不能承载唯一信息。
- 输入错误需要与字段建立程序化关联，并明确恢复方式。
- 开关同时暴露标签和当前状态；禁用态说明原因。
- 对话流使用合理的标题层级和消息语义；新回复到达时避免抢走当前焦点。
- 仅凭截图无法确认真实对比度、读屏语义、焦点顺序、键盘路径和动效舒适性，交付前必须做实际产品测试。

## 9. 设计令牌

推荐令牌层级：

```text
primitive → semantic → component
gray.100  → surface.muted → sidebar.item.selected.background
blue.500  → action.primary → switch.on.track
```

实现文件：

- `openai-unified-interface-tokens.css`：CSS 自定义属性，可直接接入 Web 原型。
- `openai-unified-interface-tokens.json`：结构化令牌，可映射到 Figma Variables、Style Dictionary 或原生端。

## 10. 组件验收清单

1. 主内容是否在超宽屏保持可读宽度，而不是被拉满？
2. 侧栏选中态是否无需依赖蓝色也能识别？
3. 当前页面是否最多只有一个视觉主动作？
4. 输入器、弹窗、菜单是否用阴影表达真正的浮层关系？
5. 设置行在窄屏是否能自然堆叠，不挤压说明文字？
6. 所有图标按钮是否有名称、Tooltip、Focus-visible 和足够点击面积？
7. 配额、错误和权限提示是否说明影响、恢复时间与下一步？
8. 危险操作是否明确对象和后果，并提供安全退出？
9. 动态内容是否不会遮挡最后一条消息或造成布局跳动？
10. 颜色、间距、圆角是否只来自令牌，而非页面级临时值？

## 11. PiWork Web 对话页实施规范

本节记录 PiWork Web 对话页基于 ChatGPT 网页端参考图完成的第二轮收敛。它是第 3、4、5 节在当前产品中的具体实现约束，后续同类页面应直接复用，不再自行发明页面级尺寸。

### 11.1 左侧栏

- 桌面端固定宽度 `260px`，背景使用 `#F9F9F9`，与白色主画布用 `1px #ECECEE` 分隔。
- 品牌区展开态只展示文字 `PiWork`，不展示应用图标；字号 `20px / 28px / 600`，左右安全边距 `20px`，底部留白 `8px`。
- 折叠态（icon rail，宽 `48px`）：品牌区显示 Logo 标记（`piwork-mark.png`，`28px`、圆角 `22%`）并居中于 `40×40px` 点击区，不在 Logo 下方重复放置第二个展开按钮。
- 折叠态 Logo 同时承担“打开侧边栏”入口：默认显示品牌图标，hover 或 focus-visible 时原位淡出 Logo、淡入 `20px PanelLeftOpen` 图标，并显示右侧深色 Tooltip“打开侧边栏”。
- 展开态右上角保持独立的 `18px PanelLeftClose` 按钮，hover 显示“收起侧边栏”；展开与收起必须复用同一个 Sidebar 状态。
- 一级导航行高 `40px`、左右内边距 `12px`、图标 `19px`、图文间距 `10–12px`；文字使用 `15px / 20px / 400` 和 `text-primary`。
- 分组标题使用 `13px / 18px` 和 `text-tertiary`，标题行高 `24px`、与列表间距 `2px`；分组之间用 `16px` 留白，不使用横线切割。
- 项目列表与最近列表文字完全统一：均为 `14px / 20px / 400`，颜色统一使用 `text-primary`，不使用次级灰；仅图标与是否展示区分层级。
- 最近对话不展示文件图标。默认、无标题和普通历史项均为透明背景；仅当前项或 hover 使用 `#ECECEC`，圆角 `10px`。
- “新对话”只在根路由选中，进入已有会话后恢复透明，避免侧栏同时出现两个选中态。

### 11.2 空白对话状态

- 顶栏无底边；空白对话状态不展示模式切换、标题或其他居中控件，只保留移动端侧栏入口。
- 欢迎区只展示一句 `我们该做什么？`，不展示品牌图标、副标题或装饰渐变。
- 主输入器最大宽度 `832px`，最小高度 `128px`，圆角 `28px`；输入区始终透明，不因有无文字切换背景。
- 输入器参考 ChatGPT 使用克制的两段式浮层阴影（`0 1px 2px 4%` + `0 8px 24px 5%`），配合 `1px` 边框；聚焦时只加深边框，不加深阴影。
- 欢迎标题与输入器作为一个视觉组整体上移：输入器锚点位于内容区高度约 `37.5%`，标题位于输入器上方约 `48–64px`，避免空白态重心下坠或标题与输入器脱节。
- 工具栏位于输入器内部底部：左侧附件，右侧模型、语音与发送。模型选择器无独立边框和底色，只保留模型名称与下拉箭头。
- 上下文操作放在输入器下方的弱背景承托条中：总高 `48px`、底部圆角 `16px`、背景 `#F7F7F7`、左右相对主输入器各缩进 `20px`；上缘藏入输入器背后约 `4px`（与输入器间距 `12px` 再 `-16px` 上移），仅露出约 `44px`。
- 承托条左侧依次为“项目 / 文件 / 插件”：项目进入上下文选择，文件直接打开附件选择器，插件进入扩展选择；不提供“打开桌面应用”入口。窄屏优先隐藏插件，项目与文件始终保留。
- 承托条在层级上位于输入器之下（输入器卡片 `z` 层级更高）：白色卡片连同其边框与浮层阴影始终覆盖灰条上缘，禁止让灰条盖住输入器的边框、圆角或阴影。

### 11.3 已有对话状态

- 顶栏左侧展示 `项目 / 对话标题 · 工作`，右侧展示分享、更多和设置；标题过长时单行截断。
- 用户消息右对齐，使用 `accent-soft`，最大宽度 `70%`；助手回复继续使用无头像、无气泡的文档式排版。
- 正文与对话输入器的外层轨道最大宽度 `832px`；扣除桌面端左右各 `32px` 内边距后，实际阅读和输入宽度为 `768px`。中文正文使用 `15px / 24px`，消息组间距 `32px`。
- 底部输入器切换为单行胶囊，最小高度 `64px`、圆角 `32px`；附件、输入、模型、语音和发送在同一行内排列。
- 输入器上方居中显示 `PiWork 可能会出错，请核查重要信息。`，使用 `12px` 三级文字，不抢占任务内容层级。
- 多行输入、附件或 Skill 标签出现时允许输入器向上增长，但底部操作保持贴近输入器右下区域。

### 11.4 响应式与状态

- `<768px` 时侧栏继续使用抽屉；顶栏隐藏项目名和分享文字，仅保留必要图标与截断标题。
- 空白态项目上下文条在窄屏隐藏次要操作，保证项目选择与主输入区不横向溢出。
- 模型名称必须截断，不能挤压语音与发送按钮；发送和停止按钮始终保持 `40×40px`。
- 输入器有文字、无文字、聚焦、附件上传和流式生成时都保持同一表面颜色，状态依靠文字、按钮和轻边框表达，禁止整块换色。
- 侧栏使用系统无衬线字体栈；品牌 `20px / 600`，一级导航 `15px / 20px / 400`，项目与历史 `14px / 20px / 400` 且颜色统一为 `text-primary`。选中态仅改变背景，不增加字重。
